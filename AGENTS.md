# Repository Guidelines

## Project Overview

Documentation website for [AssettoServer](https://assettoserver.org) (custom Assetto Corsa server, focus on freeroam), built with **Docusaurus 3.9.2** (pinned exact). Contains two documentation sets — free/public docs and Patreon-supporter-only docs — served as a dark-mode-only static site deployed to GitHub Pages.

## Architecture & Data Flow

Two instances of `@docusaurus/plugin-content-docs` share one config surface:

- **Public docs**: classic preset's default docs plugin → `docs/` rendered at `/docs`. Current version labeled `0.0.55` (`docusaurus.config.js` → `presets.docs.versions.current`).
- **Patreon docs**: second plugin instance `id: 'patreon-docs'` → `patreon-docs/` rendered at `/patreon-docs`. Current version labeled `Unreleased`.

Both use `sidebars.js` with a single filesystem-autogenerated sidebar (`{type: 'autogenerated', dirName: '.'}`); ordering comes from `_category_.json` (`position`, `label`) and frontmatter `sidebar_position` — never manual sidebar entries. Navbar version dropdowns are wired per plugin via `docsPluginId`.

**Versioning flow**: `pnpm docusaurus docs:version <version>` snapshots current content into `versioned_docs/` + `versioned_sidebars/` (manifest `versions.json`) and `patreon-docs_versioned_docs/` + `patreon-docs_versioned_sidebars/` (manifest `patreon-docs_versions.json`). These snapshots are **committed frozen copies, not auto-synced** — edits to current docs do not propagate to old versions. Don't hand-edit versioned dirs unless deliberately patching a released doc.

**Client module**: root `atob.js` is registered in `clientModules` and decodes `innerHTML` of all `.atob` spans on route change — used by `src/pages/impressum.md` to keep German legal contact info (base64) out of search indexing.

**Content pattern for config references**: YAML reference files live in `docs/plugins/reference/` and `patreon-docs/plugins/reference/` (no frontmatter), and are embedded via `raw-loader`:

```mdx
import CodeBlock from "@theme/CodeBlock";
import cfg from "!!raw-loader!./reference/plugin_geo_ip_cfg.reference.yml";

<CodeBlock language="yaml" title="plugin_geo_ip.cfg.yml">{cfg}</CodeBlock>
```

## Development Commands

```bash
pnpm install                  # install deps
pnpm start                    # dev server, live reload (alias of docusaurus start)
pnpm build                    # production build into build/
pnpm serve                    # serve the built site locally
pnpm clear                    # clear Docusaurus cache (.docusaurus) when builds misbehave
pnpm docusaurus docs:version 0.0.55   # cut a new public docs version (updates label first in docusaurus.config.js)
pnpm deploy                   # deploy to GitHub Pages (org compujuckel / project AssettoServer)
```

No lint, format, or test commands exist.

## Code Conventions & Common Patterns

**Docs content (the bulk of edits)**
- Frontmatter at file start: `title`, `description`, `sidebar_position`, `draft` (e.g. `patreon-docs/plugins/PatreonDynamicSkinsPlugin.md` is a draft). Root pages typically rely on frontmatter `title` instead of an H1.
- `.mdx` for pages using components (`CodeBlock`, `Tabs`); `.md` for plain markdown — but a few `.md` pages import `Tabs`, so extension is convention, not rule.
- Admonitions: `:::note` / `:::tip` / `:::caution` / `:::danger` (optional trailing title), closed with `:::`.
- `Tabs`/`TabItem` with `groupId` + `default`; add className `hidden-tab-labels` for icon-only tabs (styled in `custom.css`).
- Code fences: specify `language` (yaml/ini/shell/xml/sql/md) and a `title` attribute for config filenames; `<details><summary>` for long snippets.
- New plugin doc → create `plugins/<Name>Plugin.md`, put its default config in `plugins/reference/plugin_<name>_cfg.reference.yml`, import via raw-loader as above.

**React/JS**
- Stock theme components only (`@theme/Layout`, `@docusaurus/Link`, `useDocusaurusContext`); no swizzled components in `src/theme` — prefer CSS overrides over swizzling.
- Styling: CSS Modules (`*.module.css`) for page/component-local styles; `src/css/custom.css` for global Infima variable/theme overrides. Combine classes with `clsx`, plus Infima utility classes (`col col--4`, `text--center`, `button button--secondary`).
- Config files are CommonJS (`module.exports`) with `// @ts-check` and JSDoc type annotations.

**Site behavior to preserve**
- Locale strategy: English (default) at `/`, `zh-Hans` at `/zh-Hans/`. `pnpm build` builds **both** locales. Current-version docs are fully translated under `i18n/zh-Hans/`; old versions (0.0.50–0.0.54 / 0.0.34–0.0.39) stay English by design — `/docs/` serves the latest released version (English), `/docs/next/` serves the translated current version. When translating headings that are link anchors, add explicit `{#english-anchor}` IDs to keep links working (e.g. `## UI 自定义 {#ui-customization}`).
- Dark mode only (`colorMode`: `defaultMode: 'dark'`, `disableSwitch: true`).
- `editUrl` points at `github.com/compujuckel/assettoserver-docs/blob/master/`; `showLastUpdateTime: true`.
- Any new element whose text must stay un-indexed: base64-encode it in a `<span className="atob">` (decoded client-side by `atob.js`).

## Important Files

- `docusaurus.config.js` — site metadata, both docs plugin instances, version labels, navbar/footer, Prism themes, `clientModules` (`atob.js`)
- `sidebars.js` — autogenerated sidebar shared by both docs instances
- `versions.json` / `patreon-docs_versions.json` — version manifests
- `atob.js` — client-side base64 decoder for `.atob` spans
- `src/css/custom.css` — brand palette and theme overrides
- `babel.config.js` — Docusaurus Babel preset only
- `pnpm-workspace.yaml` — `minimumReleaseAge: 10080` (see below)

## Runtime/Tooling Preferences

- **Package manager: pnpm** (lockfile v9; no `packageManager` field). No npm/yarn lockfiles — don't introduce them.
- **Node >= 16.14** (engines field).
- `pnpm-workspace.yaml` sets `minimumReleaseAge: 10080` (7 days): newly published package versions are blocked for a week. Upgrading Docusaurus to a just-released version will fail resolution — expected, not a bug.
- Docusaurus packages are pinned to exact `3.9.2`; React `^18.2.0`.

## Testing & QA

**No automated tests, linter, formatter, hooks, or CI** (no `.github/`). Verification is manual:

1. `pnpm build` — the primary correctness gate. `onBrokenLinks: 'throw'` fails the build on any broken internal link; `onBrokenMarkdownLinks: 'warn'`. After renaming/moving a doc, run a build and fix all reported links (including inside `versioned_docs/` snapshots if they linked to it).
2. `pnpm start` — visually confirm content/layout changes in the dev server before finishing.
3. When adding a page, ensure ordering via `sidebar_position`/`_category_.json` and check it appears correctly in the navbar dropdown for the right plugin (`docs/` vs `patreon-docs/`).
